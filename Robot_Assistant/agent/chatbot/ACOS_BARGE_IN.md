# ACOS 连续对话与语音打断

本工程在初始化 ACOS 时显式选择 `RealTime`，覆盖 NVS 中旧的半双工设置。
首次联网后仍需说 “你好小益”。进入会话后，播放期间也持续采集、编码并上传
经过板载回采 AEC 处理的麦克风音频。ACOS 检测到新语音时停止本地旧回答；
句首在检测事件返回之前就已上传，不需要等打断后重新开始录音或补发缓存。
这不是 SD 卡录音功能。待机时禁止上传麦克风数据。

## 打断处理

- 语音开始事件优先处理，不排在长回答的音频缓存之后。
- 收到音频时分配本地回答序号。打断后过滤同一旧回答的排队数据和迟到数据，
  保留新问题的上行队列。
- 解码器停止、重启和音频喂入在同一状态任务组中串行执行。
- 如果服务端已经发送完旧回答，只清理本地播放，不再发送取消请求。
  否则由上行网络线程发送取消；“没有活动回答可取消”不作为断线处理。
- 回答播放时暂停空闲计时；结束后连续 60 秒无语音回到等待唤醒。

打断依赖 AEC 的实际效果以及 ACOS 返回语音开始事件的速度。它不是纯离线
打断，网络延迟会影响停播速度；高音量、强反射环境仍需测试残余回声误触发。
上行队列限制为约一秒，网络持续阻塞时会丢弃过期数据，不能保证弱网下句首完整。

## 烧录后验证

1. 使用已经通过连续问答测试的 Wi-Fi/手机热点，保持音量 40。
2. 启动日志应出现 `ACOS real-time mode`。联网后未说唤醒词时不应上传语音。
3. 说 “你好小益”，提出需要较长回答的问题。播放时保持安静，确认不会自己打断。
4. 播放中直接说“昨天的日期呢？”，不要说唤醒词。应出现
   `ACOS barge-in: user speech`，旧声音停止，随后回答新问题。
5. 测试回答刚开始、回答中段、回答快结束时的打断，连续进行至少五次。
   检查是否丢失句首、是否又播放旧回答，以及是否发生 WebSocket 重连。
6. 保留唤醒词打断方式，再测试一次“你好小益”打断。
7. 回答结束后安静一分钟，应出现 `AFE idle timeout`。此后普通问题不应触发
   对话，重新说 “你好小益” 后可继续。

编译包含回答队列策略的静态断言：重复取消、迟到旧音频、服务端先结束而本地
仍有缓存，以及下一轮音频恢复。这些检查不替代真实设备上的 AEC 和网络测试。
